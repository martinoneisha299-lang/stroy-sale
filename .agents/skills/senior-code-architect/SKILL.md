# Скилл: Senior Code Architect & Root-Cause Engineering

Этот скилл регламентирует принципы написания промышленного кода, архитектурного анализа, рефакторинга и бескомпромиссной отладки дефектов.

---

## 1. Лестница минимализма (The 7-Rung Ponytail Ladder)

Перед тем как написать любую строчку кода, агент обязан пройти 7 ступеней фильтрации:

```
1. Нужно ли это вообще создавать?  → Нет: удалить / пропустить (YAGNI)
2. Уже есть в кодовой базе?       → Переиспользовать существующее (shell_common.py, app.js, _data/*.json)
3. Есть в стандартной библиотеке?   → Использовать встроенные средства языка
4. Есть в нативном HTML5 / CSS3?   → Использовать нативный браузерный API (dialog, date, aspect-ratio)
5. Есть в уже подключенном пакете? → Использовать его без добавления новых зависимостей
6. Можно решить в 1 строку?        → Решить в 1 строку
7. И только если ничего не подошло → Написать минимально необходимый надежный код
```

> **Золотое правило**: *«Лучший код — это код, который не пришлось писать. В нем 0 багов, 0 уязвимостей и 100% аптайм.»*

## 2. Защита от инженерных ловушек LLM (Karpathy Pitfall Guards)

1. **Запрет на оверинжиниринг (Anti-Overbuilding)**: Не создавать класс/компонент на 300 строк там, где достаточно стандартного тега или функции на 10 строк.
2. **Запрет на галлюцинирование зависимостей**: Не предлагать сторонние npm/pip пакеты, если задача решается стандартным JS/CSS/Python.
3. **Хирургическая точность (Surgical Changes)**: Изменять только те строки, которые относятся к задаче. Не трогать соседний рабочий код (0 регрессий).
4. **Уборка за собой**: Удалять неиспользуемые переменные, закомментированный мусор и мертвый код.

---

## 3. Протокол отладки первопричин (Root-Cause Debugging)

1. **Запрещенные антипаттерны**:
   - ❌ Никаких скрытых `try/catch` или `except: pass` без логирования.
   - ❌ Никакого удаления падающих валидаторов/проверок вместо их исправления.
   - ❌ Никакой подмены упавших запросов фиктивными заглушками без уведомления.
2. **Алгоритм 5 Why**:
   - Шаг 1: Извлечь полный трейсбек и код возврата инструмента/команды.
   - Шаг 2: Изолировать корень проблемы в источнике данных или логике.
   - Шаг 3: Внести минимальное системное исправление в источник.
   - Шаг 4: Повторно запустить валидатор и подтвердить статус `exit code 0`.

---

## 4. Чек-лист Senior-разработчика перед сдачей кода

- [ ] Пройдена лестница минимализма (код максимально компактен и надежен).
- [ ] Ошибки не маскируются (нет пустых `catch` / `except`).
- [ ] Нет магических чисел и захардкоженных строк (использованы токены `tokens.css` и константы).
- [ ] Все интерактивные элементы поддерживают 8 состояний.
- [ ] Запущены все валидаторы и генераторы (`exit code 0`).
- [ ] Нет горизонтального скролла на мобильных устройствах (375px).
